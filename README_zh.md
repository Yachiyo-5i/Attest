**Attest** 回答一个更窄、但可以被统计检验的问题：

> 待测端点的行为是否仍与其宣称模型的参考基线一致？

Attest 不尝试凭几次对话"猜出模型是谁"，也不相信响应里的 `model` 字段、HTTP header、或模型自称"我是 GPT/Claude"——这些都由服务端控制，无法证明真正执行推理的是谁。

## 能检测什么

- **固定替换**——所有请求被更便宜或更旧的模型悄悄处理，却标成高价模型。
- **降级版本**——新模型被同系列的旧版或低档模型替代。
- **量化 / 部署变化**——用低精度部署降低成本，导致输出分布漂移。
- **动态路由**——简单问题走便宜模型，困难问题才上昂贵模型。
- **请求改写**——注入 system prompt、锁定采样参数、截断上下文、改写工具调用。

输出是可复现的证据报告，而不是"真/假"的武断判定。Attest 刻意区分*与参考不兼容*、*疑似混合或动态路由*、*传输被改写*、*证据不足*——不会把单次统计异常直接说成欺诈。

## 工作原理

### 核心思想：行为指纹

当 LLM 被要求随机选一个数字、颜色、字母或城市时，它的回答**并不均匀**。训练数据、tokenizer、后训练方式和采样栈共同形成稳定的、因模型而异的偏好。同一个模型可能反复偏好某几个数字，而另一个模型偏好不同。

单个回答没有鉴别力。但**同一问题经过多次采样后形成的答案经验分布**就是指纹。Attest 先从可信参考收集这个分布，再测量待测端点的分布相对它漂移了多远。

### 参考网关基线

Attest 从不直接调用厂商官方端点，也不要求每个模型单独配 API key。所有参考基线都通过**你提供的唯一参考网关**采集——一个 base URL、一个 key，由它转发到各个厂商和模型。

这样做有两个原因：

1. 参考与待测在**完全相同的条件**下测量——同样的 system prompt、同样的 prompt 模板、同样的 temperature / top-p / token 上限、同样的协议适配器、同样的探针电池版本。
2. 网关自身对请求的任何改写都会成为基线的一部分，比较因此保持诚实。

每个 模型 + 协议 组合产出一个独立的、带版本的 **Profile**（即基线）。Profile 带有校准质量门槛且会过期；过期或质量不达标的基线不能用来得出可信结论。

### 探针电池

第一层使用一组跨多个类别的短回答探针：

| 任务 | 答案空间 | 探测什么 |
|---|---|---|
| 随机数 1–10（中、英） | 闭集 | 低成本、稳定的分布 |
| 抛硬币 | 二元 | 弱信号 + 一致性检查 |
| 随机颜色 | 规范化开放集 | 文化 / 词汇偏好 |
| 随机字母 | 闭集 | tokenizer / 训练偏好 |

每个问题（一个"cell"）采样多次。Prompt 在**等价模板间随机化**——同义改写、标点、大小写、执行顺序每次请求都变——使电池无法被识别并通过对固定公开 prompt 的匹配来规避。

### 距离度量

对每个 cell，Attest 计算参考与待测答案分布之间的 **Jensen–Shannon 散度（JSD）**：

```
m = (p + q) / 2
JSD(p, q) = ½ · KL(p ‖ m) + ½ · KL(q ‖ m)
```

JSD 对称、有界，且允许两侧有不同的支持集——适合稀疏类别分布。聚合距离是各 cell 的加权平均，**仅在每个 cell 都有足够可比较证据时才计算**；证据不足时聚合距离为 `null`，绝不会伪造成高距离。

由于小样本有噪声，每次运行都做 **bootstrap**：在每个 cell 内有放回地重采样，重新计算聚合 JSD，产出 95% 置信区间。只有当整个置信区间越过该模型专属阈值时才报告明确的不兼容。处于临界的结果标为 `INCONCLUSIVE`。

### 每模型独立校准阈值

Attest 不对所有模型共用一个固定 JSD 阈值。不同模型、不同服务栈的自然方差不同。每个 Profile 带有自己的 **match / mismatch 阈值**，中间保留灰区：

```
D ≤ match_threshold     →  与参考一致
D ≥ mismatch_threshold  →  与参考不兼容
两者之间                →  无法判定，增加采样或复测
```

如果校准数据不足以同时满足误报率和漏报率目标，系统拒绝给出明确结论，而不是强行设阈值。

### 传输与完整性层

行为漂移不一定是换了模型——中转站可能改写了请求。因此协议层独立检测、单独报告：

- 响应的 `model`、request id、usage、finish reason 是否存在且自洽
- 采样参数（temperature、max tokens、reasoning）是被接受、拒绝还是被静默忽略
- 上下文是否被静默截断
- 工具 schema / 工具调用参数 / 结构化输出是否被改写
- system prompt 注入或泄露的迹象

这些信号不能证明底层模型身份，但能解释指纹*为什么*漂移。模型自报身份只记入权重接近零的辅助字段——任何服务都可以预设"你是 Claude/GPT"。

## 判定状态

- `CONSISTENT_WITH_REFERENCE`——当前证据下未发现与参考的统计不一致。
- `INCOMPATIBLE_WITH_REFERENCE`——统计检验拒绝与参考一致。
- `MIXED_OR_DYNAMIC_ROUTING`——待测端点自身呈现多个后端或随时间变化的行为。
- `TRANSPORT_OR_PARAMETER_ALTERED`——请求、上下文、流或工具调用可能被中间层改写。
- `INCONCLUSIVE`——采样、协议或基线证据不足，无法形成可靠结论。

`CONSISTENT_WITH_REFERENCE` **不是**密码学证明。没有可信执行环境、远程证明或厂商签名时，纯黑盒检测只能提供统计证据。

## Attest 不能证明什么

- 某个精确 checkpoint 一定生成了响应。
- 差异一定来自恶意替换，而非厂商更新、量化、采样器或安全层变化。
- 通过检测的服务商永远不会在检测之外的流量上换模型。
- 行为一致等价于权重逐字节相同。

## 部署

Attest 以**单容器**交付：React 前端编译为静态文件，由 FastAPI 后端提供。`/data` 是唯一需要持久化的目录（SQLite 数据库、基线、报告）。

```bash
docker compose up -d
```

然后打开 `http://127.0.0.1:8321`，用 `docker-compose.yml` 里配置的密码（`ATTEST_AUTH_PASSWORD`）登录。生产环境请在容器前放置 HTTPS 反向代理，并设置 `ATTEST_COOKIE_SECURE=true`。
